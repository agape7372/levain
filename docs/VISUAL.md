## 1. 씬

### 1-1. 카메라: 직교 42° 틸트 3/4 부감 (개정 2026-11-19)

```
CAM_ELEV_DEG = 42                  // 시선 고도(lookAt 기준). SceneHost.setCameraElevation
camera.position = (0, LOOK_Y + 9.12·sin42°, 9.12·cos42°) ≈ (0, 6.74, 6.78)
camera.lookAt(0, 0.64, 0)          // LOOK_Y — 상단 HUD 헤드룸 + 아래 위치 알약과 틈 (개정 2026-11-19 판정 L4: 0.8 → 0.64)
frustum viewH = 5.4                // 세로폰에서 병+헤드룸 55~65% 점유
```

**고도 교정(2026-11-19, A1-16)**: 이전 표기 「atan(8/5.6) ≈ 55°」는 lookAt y(0.8)를 빼먹은 값이었다. 실제 시선 고도는
atan(7.2/5.6) = **52.1°**였다. 반죽 모델 v2에서 52.1° · 44° · 42° · 38°를 같은 프리셋으로 찍어 비교하고 42°로 내렸다
(`node scripts/motionlab-shot.mjs --queries <dir> j42="preset=justfed&cam=42" …`). 직교 투영이라 아래 수치는 해석값이다
(반죽 반경 0.912, 갓 밥준 수위 0.76, 피크 1.596).

| 고도 | 갓 밥준 옆벽 ÷ 반죽 실루엣 | 윗면 타원 단축(52.1° 대비) | 병+립 화면 높이 |
|---|---|---|---|
| 52.1°(이전) | 24.5% | 100% | 2.62 |
| 44° | 30.1% | 89% | 2.64 |
| **42°(채택)** | **31.6%** | **85%** | **2.64** |
| 38° | 34.8% | 78% | 2.63 |

기준: 옆벽 30% 이상(높이 변화가 보여야 성장이 읽힌다) · 터치 면(윗면 타원) 65% 이상 · 병 점유율 유지. 병 화면 높이가
`1.9·cos θ + 1.84·sin θ`라 38~52°에서 거의 같아 VIEW_H·LOOK_Y는 그대로 둔다. 38°는 앞 입구 테가 반죽 윗면을 가리기 시작해 뺐다.
홈 HUD 겹침은 `node scripts/qa-shots.mjs <dir> --screens=home`으로 본다.

**LOOK_Y 0.8 → 0.64(개정 2026-11-19 판정 L4)**: 위치 알약(실온 · 창가 · 냉장고)이 병 바닥 앞쪽을 CSS 약 20px 덮었다(p360).
직교 프러스텀이 `top = VIEW_H/2 + LOOK_Y`라 LOOK_Y를 ΔL 내리면 화면 위 모든 점이 (1 + cos θ)·ΔL ≈ 1.74·ΔL월드 올라간다
(p360 캔버스 688px 기준 0.16 → CSS 약 36px). 실측(F1 · F3 · F4 · F8, p360 · p390): 병 바닥 ~ 알약 틈 p360 CSS 16px · p390 34px,
입구 테 위 ~ 머리 글(진행 막대) 틈 p360 약 95px — grab 상한(JAR_HEIGHT + 0.12)도 머리 글에 닿지 않는다. VIEW_H는 그대로.

근거: 부피=성장을 "병 눈금 대비 높이"로 화면 안에서 보여야 게임이 성립(탑다운 탈락).
순수 측면 뷰는 유리 투과 렌더 필수 → 모바일 알파 소팅 지옥(탈락). 42°는 반죽 윗면(현 셰이더의
주 무대)이 여전히 주인공이면서 병 측벽·높이가 함께 보이고, y=0 평면 레이캐스트도 무수정 동작.

### 1-2. 유리병 — 3패스 고정 renderOrder (굴절·transmission 금지)

직벽 원통(반지름 0.92 — 기존 토러스 반경 계승, 높이 1.9, radial 48), 입구 살짝 벌어진 립.

2026-11-14 추가: Blender 파이프라인 PBR 빵(노멀·거칠기 맵이 있는 GLB)은 `MeshStandardMaterial`(금속성 0)로
그리고 방 환경맵은 **반사만** 싣는다(`src/render/breadMaterial.ts` — IBL 확산 줄을 셰이더에서 뺐다). 그래서 확산항은
아래 Lambert 유도와 같은 식이고 같은 노출 캘리브레이션을 받는다. 확산 IBL을 넣으면 전 색이 허옇게 바랬다(실측).

**유도**: 빵 GLB는 `MeshLambertMaterial`(런타임·하네스 공통 `forceLambert` 강제 교체)로 렌더되고,
윗면(normal +Y)의 출력은 `albedo · (dotNL_key·Ik + dotNL_fill·If + Ia) / π`다(three 0.185, 기본
`NoToneMapping`+`SRGBColorSpace`, 색관리 활성 — 물리 단위 라이트). 키·필 위치가 고정이라
`dotNL_key = 6/√44 ≈ 0.9045`, `dotNL_fill = 3/√19.25 ≈ 0.6838`(둘 다 좌표 기하로만 결정, 카메라
각과 무관). 이 항이 정확히 π가 되면 윗면이 정본 hex 그대로 나온다 — 세 세기를 그 식에 맞춰
역산(`Ik=2.4, If=0.3` 고정 시 `Ia = π − dotNL_key·Ik − dotNL_fill·If ≈ 0.7656`). 3灯을 전부 순백으로
두면 R/G/B가 항상 같은 배율을 받으므로 "채널 편향 없음"이 산수로 보장된다.

세 빵의 비가 0.89~1.05로 모여 **측/윗 비 목표 ≈ 0.9**로 잡았다(±10% 허용 시 0.81~0.99를 커버).

**메커니즘**: `HemisphereLight(sky=0x000000, ground=0xffffff, intensity)`를 key/ambient/fill과 별개로
추가한다. three의 `getHemisphereLightIrradiance`는 `mix(ground, sky, 0.5·dot(N,up)+0.5)`이고, 이
값도 ambient와 동일하게 `RE_IndirectDiffuse`에서 `albedo/π`를 곱해 최종 출력에 더해진다(직사광의
`dotNL·color`와 같은 합산 경로). `sky=검정`이므로:
- 윗면(N=(0,1,0)): `dot(N,up)=1` → 가중치가 100% sky(검정)로 쏠려 기여 = 0. **윗면 파리티가 산수로
  그대로 유지**된다(회귀 없음 — key/ambient/fill 세 값은 1차 캘리브레이션 그대로 손대지 않았다).
- 수직 측벽(N·up≈0): 가중치 0.5 → `0.5·ground/π`만큼 순증. 앰비언트 재조정이 불필요하다(sky=0이라
  윗면에서 상쇄할 것이 없다).

`intensity`는 이론상 수직면에 `0.5·intensity/π`를 더하지만, three의 색공간 관리(선형 계산 후
sRGB 인코딩)가 있어 sRGB 픽셀 기준 실측 증분은 이론치보다 작다(intensity 1.7 → 이론 +0.27, 실측
scone/loaf 측벽 +0.16) — 최종 값은 실측으로 맞췄다. **확정값: intensity=1.7**
(`scripts/breadlab.ts`·`scripts/thumbsHarness.ts`·`src/render/SceneHost.ts`의 `SHOWCASE_LIGHT.hemi`
세 곳 동일). `HOME_LIGHT`엔 `hemi` 필드가 없다 = 홈 씬은 계속 hemisphere 0(끔), 쇼케이스
진입/이탈 시 `applyLightRig`가 `rig.hemi ?? {intensity:0}`으로 스왑한다.

## 2. 기포 시스템 (파티클 아님 — 셰이더 절차)

- `uBumpPos[4]/uBumpAmp[4]` 공유 배열을 기포에 전용(개정 2026-11-19: 8 → 4 — 동시 상한이 4라 나머지 슬롯은 늘 비어 있었다). CPU에서 생명주기만 관리
  (스폰 간격 = `lerp(6s, 0.8s, uBubbleDensity)`), 셰이더는 배열만 읽는다.
- 기포 생명주기(개당 2~4s): 부풀기(0→max, easeOut) → 정점 유지 → **터짐**: 80ms에 바늘구멍 깊이(`SCAR_AMP` 0.004)로
  꺼지고, 그 자리에 **바늘구멍**이 `SCAR_SEC` 4초 동안 남았다 easeOut으로 옅어진다(그동안 슬롯을 비우지 않는다) → 소멸.
  터질 때 뽀글 사운드(§6).
  **개정 2026-11-19 R2-08**: 돔이 k 16~26 · 진폭 0.06~0.11(월드 1.2cm 혹, 옆에서 보면 윗면 모서리에 혹이 섰다)이던 것을
  **k 60~140 · 진폭 ≤0.022(상한 0.025)**의 작고 날카로운 돔으로 줄였다. 팝 링 하이라이트(`q·e^-q`)는 폐기하고, 프래그가
  음수 슬롯을 범프 루프 안에서 바늘구멍(반죽보다 살짝 어두운 점, exp 추가 0)으로 그린다. 살아 있는 움직임의 본체는
  유리 너머 기포 단면이다(아래).
  (개정 2026-08-24: 함몰 −0.3 → −0.12 + 링 실장 — 어두운 원형 함몰 회피, 확장기획 §4-2b 근거)
- **동시 가시 상한 4개** — 슬롯 수 = 상한(`DYN_SLOTS`). 자연 스폰은 빈 슬롯이 없으면 건너뛰고, 탭 유도(`spawnNow`)는 가장 오래된 기포를 대신한다 (밀집 클러스터 회피, 목표 2~4개 §4-1).
- **슬롯 전부 동적 기포(양수 돔)** — 레거시 함몰 4개(음수 진폭)는 폐기. 휴지 실루엣은 고정 혹 대신
  시간 정지 2옥타브 FBM(`fbm(p.xz·1.8 + 상수시드)·0.05`)이 대체 — 비대칭 유기 블롭.
- **agitation**(드래그 속도 0~1, `bubbles.update`에 전달): 젓는 동안 스폰 간격 ÷3·수명 ÷2 —
  부상·팝 가속. 손을 떼면 즉시 원복(누적 없음).

### 2-1. 칸마다 기포 하나 — 유리 너머 단면 · 윗면 바늘구멍 (신규 2026-11-19 P1b · R2-04 · R2-07 · A1-06)

옛 유리벽 기공(`cellField` 2옥타브 sin·cos 곱 문턱 + 세로 늘임 ×0.62 + 막 등고선)은 **세로 줄 · 4엽 별 · 밝은 벌레 줄**을 그렸고,
윗면 기공(FBM 문턱 pin · crater)과 피크 crackle은 **회색 멍**으로 읽혔다. 전부 지우고 지터 셀 한 함수(`cellBubble`)로 바꿨다.

- **자기 칸만 본다**(3×3 이웃 탐색 없음): 칸마다 기포 하나, 반지름을 칸의 0.36 안으로 묶고 중심을 그 안에서 지터한다.
  칸 비움 확률(`pres`) · 줄마다 무리수 밀림(0.618) · 칸마다 타원비 ×0.8~1.25 · 휨(납작할수록 더 휨) · 크기 제곱 분포
  (작은 것이 많다)가 격자를 지운다. trig 0.
- **해시 `hash3`**: 칸 번호를 37로 접고 중간값을 16 아래로 묶어 mediump(fp16)에서도 소수 7비트가 남는다.
  옛 `fract(sin(x)·43758)`은 fp16에서 줄무늬로 무너진다 — 반죽 셰이더에서 퇴출(테스트가 잠근다).
- **유리 너머 단면 3층**(원통 매개 = 호 길이 × 높이, 월드. `atan` 분기컷은 보이지 않는 뒤쪽 옆벽):
  | 층 | 칸(월드) | 반지름 | 있음 확률 | 색 |
  |---|---|---|---|---|
  | 잔 기포 | 0.05 | 0.006 ~ 0.009→0.016(크기 축) · 아래 ×0.8 / 위 ×1.15 | 세기 × (아래 0.6 → 위 0.32) | 따뜻한 그늘 ×(0.925, 0.895, 0.845)·0.75 |
  | 중간 | 0.11 × 0.13 | 0.012 ~ 0.022→0.04 · 아래 ×0.75 / 위 ×1.2 | 세기 × (0.15+0.5·크기) × (아래 0.35 → 위 0.75) × 하강 위쪽 −60% | 그늘 ×(0.905, 0.87, 0.815) ≈ ΔL* −10 |
  | 큰 주머니 | 0.21 × 0.18 | 0.04 ~ 0.068(둥긂 0.9) | 세기 × ripe × 0.6, 높이 0.6~0.86 띠(윗면 바로 아래, 실물 09) | 따뜻한 옅은 그늘 ×(0.95, 0.925, 0.885) + 위 테만 살짝 밝게, 테두리 선 없음(개정 2026-11-19 아트 판정: 가로 납작 렌즈가 줄지어 쌀알 · 씨앗 · 감은 눈, 밝은 회백 + 짙은 테는 눈알 · 진주로 읽혀 둘 다 버림) |

  피크 = 중간 층이 세로로 늘어난 터널(타원비 1 → 1.9) + 윗면 아래 큰 주머니 띠, 갓 밥준 = 드문 잔 기포, 배고픔 = 적음.
  테 바로 아래 1px 세로 실선(판정 L2)은 벽 기포가 아니었다(wallCells 0에서도 남음) — 유리에 올라붙은 메니스커스 끝(rr 0.93~0.985)에서 xz 칸 바늘구멍 · 거품 점이 세로로 늘어난 것이라 거기서 끊는다(§2-1 윗면).
  칸마다 휨(`cellBubble`): 부호 · 크기를 칸 해시로 크기와 따로 섞고 최대 0.2/타원비(옛 0.3, 크기와 같은 해시라 큰 칸이 전부 위로 볼록 = 「감은 눈」 위험, 판정 L1).
  세기 = `wallCells`(기운 반영), 크기 축 = `(80 − cellFreq)/46`. 위 테두리만 부드럽게 밝다(+0.05). 막 등고선 · 별 · 줄무늬 없음.
  잔 기포 · 중간을 회색으로 두면 먼지 · 물감 튄 자국으로 읽혀(첫 캡처) 따뜻한 그늘로 바꿨다(실물 07의 어두운 구멍 = 따뜻한 갈색).
  **움직임**: 흐르는 스크롤 없이 칸마다 위상이 다른 부드러운 삼각파로 반지름이 ×0.88~1.0을 오간다(주기 50~250초, 활동 비례).
- **윗면 바늘구멍**(칸 0.07월드): 있음 확률 `pinholes × 0.7`. 배고픔(ripe 0) = 반지름 0.007~0.011의 고른 잔 점, 피크(ripe 1)
  = 0.005~0.022로 들쭉날쭉하고 **큰 구멍만 밝은 테**(작은 분화구). 색은 따뜻한 그늘 ×(0.945, 0.932, 0.91) — 검정 금지.
- **가장자리 잔거품 띠**(칸 0.032월드): 윗면 반경 0.80~0.97 구간, `foam`(오르는 중 · 피크). 살짝 밝고 차가운 거품 톤(R1 #dedfdc) + 아주 작은 구멍.

### 3-4. 전환 정책

- WebGL 컨텍스트를 잃었다 되찾으면 시드·렌더 파라미터·실행 상태·쇼케이스 url을 다시 적용한다. 천 덮개 상태는 아직 잃는다(남은 흠).
- 김 파티클은 수명 끝 0.3s 동안 흐려진다(`STEAM_FADE_S`). 이전엔 툭 사라졌다.

## 5. 게임필

### 제스처 (input.ts FSM)

```
down ─ 이동<8px & <250ms 내 up → poke
     ─ 홀드 0.8s+               → 롱프레스
     ─ 이동≥8px ─ 반죽 위 시작 + 느린 끌기(<1.6px/ms) → grab(당기기, 확장기획 §4-2)
                ├ 배경 시작 + 수평 우세 + 전환 가능    → swipe(르방 전환, §5-5)
                └ 그 외(빠른 문지르기·반죽 밖 시작)      → stir(젓기, §4-1)
```
(개정 2026-08-24: 드래그 3채널 — 한 포인터 세션의 소유권은 중간에 안 바뀐다.)

개정 2026-11-19 (A1-08·A1-09):
- **쇼케이스 중엔 홈 입력 전체 차단** — `InputHooks.isBlocked`(SceneHost가 `isShowcasing()`을 넘긴다). onDown에서 조기 반환하므로 젓기 소리·햅틱·천 걷기가 쇼케이스 위에서 나지 않는다.
- **포인터 유실 복구** — onDown에서 `setPointerCapture`, `lostpointercapture`는 `pointercancel`과 같은 경로(`onCancel`, onUp처럼 pointerId 검사). up 없이 같은 id로 다시 누르면 남은 제스처(젓기 소리·grab)를 먼저 끝낸다.

| 제스처 | 트리거 | 반응 |
|---|---|---|
| **탭(poke)** | 이동<8px & <250ms 내 up | 탭 지점 가우시안 덴트(깊이 0.06, `uPokePos/uPokeAmt`) + 고체는 damped spring, 액체는 지수 완화 τ=mix(0.45,1.8,liquidity) + 커널 확산(넓어지며 얕아짐 = 아묾)(개정 2026-08-24: 반유동체 개편) + 근처 기포 1~2개 유도. 눌림 큐 최대 3 |
| **롱프레스** | 홀드 0.8s+ | 손가락 쪽 표면이 아주 천천히 0.03 부풂 — 눈 없이 "알아챈다"만. 떼면 easeOut. **구현(2026-11-19, A1-15)**: `input.ts` 홀드 타이머 → `DoughMesh.holdStart(x,z)` / 떼기 → `holdEnd()`. 탭 채널(`uPokeAmt` 음수 = 볼록, 첨도 POKE_K0/2)을 빌리고 상승 τ0.6s · 하강 τ0.3s 지수 완화. 그전에는 문서만 있고 동작이 없었다 |
| **grab(당기기)** | 반죽 위 down + 느린 드래그 | anchor 기준 **변위 추종**(`uGrabPos/uGrabDisp`) — 잡고 멈춰도 유지. 2시간척도 SLS: elastic(τ0.07s) + creep(0.7s+부터 잔류 축적). **놓기 = pointerup**. 릴리즈 시상수 분리: 리프트 τ0.35(중력 먼저) → 주름 τ0.25(`uGrabWrinkle`) → 커널 퍼짐(합류) → creep τ1.2(측방 마지막). elastic 복귀는 ζ≈0.95·ω5.5(오버슈트 ≤5%). necking(det=1) + 윈도우페인 + 겹 가닥. 상태 물성 3종(grabMax·creepGain·ζ)은 RenderParams. **확정 수치(사용자 실기기, 2026-08-24 저녁): 리프트 1.6 · 커널 k 1.6 · ω 5.5 · grabMax 피크 0.60** — GRAB_DEFAULTS·grabMax 매핑이 정본. **헤드룸 클램프(개정 2026-11-19 판정 M4)**: 리본 끝(`topY + |변위|·lift·1.7`)이 병 입구 + 0.12(월드 2.02)를 넘지 않게 lift를 `min(1.6, (JAR_HEIGHT + 0.12 − topY)/(grabMax·1.7))`로 — 피크(수위 1.6)에선 약 0.4, 배고픔 · 갓 밥준은 1.4~1.6. grabMax · ζ 잠금값은 그대로. 시뮬 효과 0 |
| **stir(젓기)** | 이동≥8px (grab 조건 밖) | 손가락 추종 시어장(`uStirPos/uStirVec`) + 끈적한 실(`uTrailPos[4]`, 개정 2026-08-24: 표기 정정), 놓으면(80ms 입력 정지) damped spring 복귀. 전신 wobble은 **stirVec(속도)을 목표로 한 감쇠 진동자**(슬로싱 — 아래 이징 예외) — 손가락 절대좌표 오프셋 폐기(개정 2026-08-24). 시뮬 효과 0 유지(GDD §5) |
| **swipe(르방 전환)** | 배경(항아리 밖) down + 수평 우세 드래그 | 후보 판정은 8px 시점의 \|dx\|>\|dy\|, **확정은 up에서 누적 \|dx\|≥48px & \|dx\|>\|dy\|×1.5**(8px 시점의 비는 터치 노이즈). 왼쪽으로 끌면 다음(+1)·오른쪽이면 이전(−1) — 칩 ‹ › 와 같은 순서·같은 경로(`api.switchStarter`). 전환은 컷(즉시 스냅·반점 시드 재설정). 차단: 르방 1마리·모달 열림·쇼케이스·연출 중(`SceneHost.canSwipe`). 확정 실패 시 아무 일도 없다(반죽 무접촉 — 레이캐스트도 생략). 시뮬 효과 0 (신규 2026-08-24) |
| **플릭(천 덮개)** | 위로 스와이프(속도 임계), 탭도 가능 | 덮개 걷기 0.6s `cubic-bezier(0.22,1,0.36,1)` — 콜드 스타트·hidden 30분+ 복귀 시에만 표시(§4-5) |

- 레이캐스트 평면은 **반죽 윗면(fill) 연동** — 고정 y=0.55 폐기, 손끝 = 눌리는 지점(개정 2026-08-24).
- **이징**: 등장·성장 `cubic-bezier(0.22, 1, 0.36, 1)` / 왕복·숨 easeInOutSine /
  탄성 복귀 damped spring `e^(−5t)·cos(12t)` (오버슈트 1회 이하). **elastic 다회 진동·bounce 금지.**
  단 **grab 복귀만 임계감쇠 근처**(위 표) — "고무줄 튕김"이 아니라 반죽의 되돌아옴.
  **예외 — 전신 슬로싱(`uWobble`)은 감쇠 진동자 1.5Hz·ζ=0.62−0.50·**fluidity**로 다회 출렁인다(액체 문법 — 개정 2026-08-25: 구 liquidity 구동 시 갓 밥준 ζ가 0.18이라 물처럼 5~6회 출렁였다).
  국소 변형(poke·stir·grab)의 다회 진동 금지는 유지.** (개정 2026-08-24: 반유동체 개편)
- 튜닝 하네스: `motionlab.html` (dev 전용, URL 파라미터 전체 상태 — breadlab 패턴).
  완료 판정은 확장기획 §4-1 목표 장면의 실기기 촬영 비교.
- **햅틱(희소)**: 밥 완료 impactLight / 해금·빵 notificationSuccess / 부활 impactMedium.
  **젓기(stir) 세션(down~up)당 최대 1회**(첫 기포 팝에 impactLight, 이후 무진동) — 연속 팝마다 울리면 소란스럽다.
  grab(당기기)는 놓을 때 light 1회(2026-11-12). 탭·기포·롱프레스·덮개 걷기 = 무진동. 설정에서 끄기 가능.

### 7-3. 타임라인과 폐기된 고무줄 마커·눈금(§1-2)의 무관함

`.hud-timeline`은 §1-2에서 폐기된 병 눈금·고무줄 마커의 부활이 아니다 — 겹치는 시각 문법이 하나도 없다:

| | 고무줄 마커·눈금(폐기, §1-2) | 발효 타임라인(신규, §7-2) |
|---|---|---|
| 축 | 세로 — 병 속 부피 | **가로 — 시간** |
| 위치 | 병 위(3D 씬) | 텍스트 스택 안(HUD, sub 문장 아래) |
| 채움 | 채워서 진행률을 말함(게이지 은유) | **채우지 않음** — 점 하나만 |
| 눈금 | 있음(병 목 표식) | **0개** |
| 숫자 | 없음(그래서 "정본이 아니다"로 폐기됨) | **0개**(같은 정보를 sub 문장이 말로 이미 전달) |

**채우지 않는다는 결정이 핵심이다** — 진행률을 칠하면 "지금 얼마나 찼나"라는 게이지 은유가 성립하고,
그건 §1-2가 "부피 정보는 도우 fill 표현 + 관찰 카드가 담당"으로 이미 정리해 둔 영역을 다시 침범한다.
타임라인은 부피를 말하지 않는다 — **"지금이 하루 리듬의 어디쯤인가"** 하나만 점으로 찍는다.
