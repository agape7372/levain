## 0. 제품 한 줄

실제 사워도우 스타터(르방)의 리듬 — 하루 1~2번 밥, 4~8시간 피크, 냉장하면 주 1회 — 을
그대로 옮긴 **실시간 다마고치**. 키워서(성장), 해금하고(레시피), 떼어 굽는다(수확).
무캐릭터·코지 톤·액션으로는 죽지 않음·완전 로컬.
실패는 하나뿐이고 예고된다 — 곰팡이. 말린 조각으로 대비할 수 있다.

## 1. 시뮬레이션 패러다임: 닫힌 함수 모델

저장 상태는 **타임스탬프 + 느린 누적값만**. 활성도·부피·단계·냄새·배고픔은 전부
`유효 경과시간 = (now − lastFedAt) × 온도배율`의 닫힌 함수로 파생한다.

- 오프라인 catch-up이 O(1) — 틱 루프·고정 스텝·remainder 없음.
- 위치(온도)는 앱이 켜져 있을 때만 바뀌므로 오프라인 구간은 항상 단일 배율.
- sim 안에 확률 이벤트 없음 — PRNG 없음. 렌더 화장품 랜덤은 render 층 `Math.random`.
- 파생 가능한 값은 절대 저장하지 않는다.

## 2. 저장 상태 (SimState)

| 필드 | 타입 | 의미 |
|---|---|---|
| `createdAt` | epoch ms | 탄생 시각. 성장 단계의 "최소 일수" 게이트 |
| `lastFedAt` | epoch ms | 마지막 급여. 활성 곡선의 원점 |
| `lastSimulatedAt` | epoch ms | 마지막 반영 시각. 시계 역행 방어 기준 |
| `feedRatio` | `'1:1:1' \| '1:2:2' \| '1:5:5'` | 마지막 급여 비율 — 곡선 시간축 결정 |
| `flour` | `'white' \| 'wholewheat' \| 'rye'` | 마지막 급여의 밀가루(§3-1-1). 급여에서만 바뀜, 구세이브 키 부재 → white |
| `location` | `'room' \| 'window' \| 'fridge'` | 병 위치 = 온도 배율 |
| `acidity` | float 0~100 | 산미 누적 |
| `maturity` | int ≥0 | 건강 급여 사이클 수 — 성장·해금 축 |
| `mass` | int 60~480 (g) | 병 속 총량 — 굽기 경제 축 |
| `reviveProgress` | `0 \| 1` | 부활 의식: 0=정상, 1=휴면 중 1회차 급여 완료(2회차 대기). 완료 시 0 복귀 |
| `locAnchorAt` | epoch ms | 위치 앵커 — 마지막 급여 또는 위치 변경 시각 |
| `effBaseMs` | ms | 위치 변경 전까지 접어 둔 유효시간. `유효경과 = effBaseMs + (now−locAnchorAt)×배율` — 세션 중 위치를 바꿔도 과거 구간이 새 배율로 재해석되지 않게 하는 회계 |
| `lastDiscardBakeAt` | epoch ms \| null | discard 레시피 "급여당 1회" 쿨다운 비교용 |
| `flake` | `{ madeAt: number; maturity: number } \| null` | 건조 플레이크 백업 1슬롯 — 말린 시점의 maturity 스냅 |

> (개정 2026-08-24, 저장 v2 — ARCHITECTURE §3) `label`(이름)과 `collection`(도감)은 sim 밖으로
> 이동: 이름은 `StarterRecord.name`(르방 개체 소유), 도감은 `shared.collection`(집의 기록 —
> 르방 폐기·삭제에도 남는다, 항목에 starterId 병기). 이름 규칙(5단계 해금·12자)은 §4·§5 그대로.

**초기 상태** (창조 의식 = 첫 급여 1:1:1):
`mass 180, lastFedAt = createdAt, feedRatio '1:1:1', flour 'white', location 'room', acidity 0, maturity 0, reviveProgress 0`.

저장하지 않는 것: 활성도·부피·기포량·냄새·현재 phase(전부 파생), 해금 비율(stage 파생),
급여 횟수(maturity 중복), 수화율(100% 고정 — 레시피 카드 맛 설명에만 등장), 온도·급여 이력 로그.

## 3. 핵심 수치

### 3-1. 온도 배율 — 모든 수치의 뿌리

| 위치 | 상정 온도 | 배율 | 의미 |
|---|---|---|---|
| 실온 `room` | 24°C | ×1.0 | 기준. 하루 1~2회 리듬 |
| 창가 `window` | 27~28°C | ×1.3 | 서두를 때 — 피크가 이르고 배고픔도 빠름 |
| 냉장 `fridge` | 4°C | ×0.08 | 유지 모드 |

검산: 배고픔 14h ÷ 0.08 ≈ 175h ≈ **7.3일** → "냉장 시 주 1회"가 같은 표에서 저절로 도출.

### 3-1-1. 밀가루 배율 (2026-08-24 신설 — 확장기획 §7-2)

| 가루 | 배율 | 의미 |
|---|---|---|
| 다목적 `white` | ×1.0 | 기준 |
| 통밀 `wholewheat` | ×1.15 | 발효 가속 — 피크가 이르다 |
| 호밀 `rye` | ×1.25 | 최대 가속 + 산미도 같이 빨라짐(산미는 유효시간당 적립이라 자동) |

- **유효시간 배율 = 온도 × 밀가루** (`rateMult`). 알림·예측·부활 게이트 전부 같은 배율.
- flour는 **급여에서만** 바뀐다(effBaseMs=0 리셋) — 균일 배율 회계의 전제.
- ×1.15/1.25는 튜닝 가설(§19-2 "방향 확정·정량 TO VERIFY"). 선택 UI는 성숙 4단계 해금(상세 펼치기).
- 렌더: 통밀 담갈·호밀 회갈 색 톤 시프트(renderParams — 상태 톤 아래 바탕).

### 3-2. 활성 곡선 (급여 후 유효시간, 1:1:1 기준)

```
0h ──── 0.75h ──── 4.5h ══ 6h ──── 12h ──── 14h(배고픔)
 잠복기    상승(smoothstep)  피크 1.0   하강 →0.25   전이
 0→0.15
```

- 잠복기 0~45분: activity 0→0.15 (급여 직후엔 조용 — 실제 현상)
- 피크 4.5~6h: activity 1.0, 부피 최대
- 하강 6~12h: 0.25까지 완만히 → 배고픔 전이

### 3-3. 급여 비율 = 플레이어의 스케줄 도구

| 비율 | 씨앗 | 피크(실온) | 배고픔 | 급여 후 mass | 리듬 |
|---|---|---|---|---|---|
| 1:1:1 (기본) | 60g | 4.5~6h | 14h | 60+60+60 = **180g** | 하루 2회. 아침 밥 → 점심 피크 |
| 1:2:2 (3단계 해금) | 60g | 7~9h | 20h | 60+120+120 = **300g** | 하루 1회. 아침 밥 → 저녁 피크 굽기 |
| 1:5:5 (4단계 해금) | **40g** | 10~12h | 30h | 40+200+200 = **440g** | 밤 밥 → 아침 피크. 제빵사 패턴 |

1:5:5의 씨앗 40g은 실제 고배율 급여 관행(씨앗을 줄인다) 그대로 — mass 상한 480g 안에 들어온다.
새 상태 변수 0개로 깊이 추가: 곡선의 시간축만 비율별로 늘어난다.
**비율 선택이 곧 스케줄 퍼즐** — "피크를 내 일상 어디에 앉힐까"가 이 게임의 조용한 전략층.

### 3-4. 상태 전이

```
활발(active) ──14h──▶ 배고픔(hungry) ──+22h──▶ 시큼(sour) ──+106h──▶ 휴면(dormant) ┬─+48h──▶ (반점) ─+72h▶ (확산) ─+96h▶ 곰팡이(종착)
  ▲                                                                                │    [반점·확산은 휴면의 파생 하위단계]      │
  │◀────────── 급여(활발·배고픔·시큼) ──────────────────────────────────────────────┘                                          │
  │◀── 부활 의식 2급여(휴면·반점·확산 — 1회차가 유효시간 리셋 = 걷어내기) ◀───────────┘                                        │
  │                                                                                                                            │
  │◀── restoreFlake(플레이크 有): maturity×0.6, createdAt 보존(이름·도감은 sim 밖 소유 — 자연 보존), reviveProgress=1 경유 ──┤
  └◀── discardStarter(새 개체): maturity 0, createdAt=now, 이름·도감(전역)·플레이크 보존 ──────────────────────────────────────┘
```

- 곰팡이에서 급여·굽기·이동·말리기 전부 차단(`moldBlocked`) — 종결 2액션(폐기·플레이크 복원)만 통과.
- 죽음은 액션으로는 불가능(씨앗 불가침 유지, §6-2) — 오직 방치 시간만이 죽인다.

시큼·휴면은 **둘 다 배고픔 시점 기준 오프셋**: 시큼 = 배고픔 +22h, 휴면 = 배고픔 +106h
(1:1:1이면 급여 후 14h/36h/120h). 큰 급여일수록 버퍼도 같이 밀린다.

- **배고픔**: 부피 꺼짐, 표면 주름. 급여하면 즉시 활발.
- **시큼**: 배고픔+48h부터 hooch(회갈 액체층) 연출. 급여 2~3회면 산미 회복.
- **휴면**: 기포 0, 색 바램, 숨 거의 정지. 급여해도 즉시 안 살아남 — 부활 의식 필요. **죽음 아님.**

### 3-4-1. 곰팡이 — 유일한 실패

휴면의 파생 하위단계로 반점→확산→사망이 진행된다. 신규 저장 필드는 0개 — `moldStage`·`mold01`·`moldDeadAt`
전부 유효 경과시간의 파생값이다. 재정박(§3-8)이 상대 간격을 보존하므로 시계를 앞뒤로 조작해도 회피할 수
없다 — **결정론**.

| 단계 | 배고픔 기준 오프셋 | 휴면 기준 오프셋 | 1:1:1 절대(급여 후) | 의미 |
|---|---|---|---|---|
| 반점 | +154h | +48h | 168h ≈ 7일 | 예고 1단계. 급여하면 즉시 회복(걷어내기, §3-7) |
| 확산 | +226h | +120h | 240h ≈ 10일 | 예고 2단계. 아직 급여로 살릴 수 있다 |
| 곰팡이(사망) | +322h | +216h | 336h ≈ 14일 | 종착 — 회생 불가. 폐기 또는 플레이크 복원만 가능 |

검산: 창가(×1.3)는 곰팡이가 더 이르다(≈10.8일 — 더위가 곰팡이를 부른다, 다이제틱 경고). **냉장(×0.08)은
사망까지 ≈175일** — 냉장이 실제로 곰팡이를 늦춘다(§3-1). 주말 여행은 무해하고, 1주 방치는 반점(회복 가능)에
그치며, 실온에서 완전히 2주를 방치해야만 사망한다 — 실패가 좁고, 예고되고, 회피 가능하다.

**조기 사망의 수용**: 3단계 미만(생후 8일 이전)은 냉장·플레이크 둘 다 미해금이라 무보험으로 방치되면 그대로
사망한다. 손실이 작고(낮은 maturity, 도감은 보존) 실제 스타터도 첫 주가 가장 취약한 것과 정합한다 —
의도적 수용.

### 3-5. 산미 (acidity 0~100)

누적(유효시간당): 활발 +0.3/h · 배고픔 +1.5/h · 시큼 +2.5/h · 휴면 +0.5/h.
급여 시 희석: ×0.55 (1:1:1) · ×0.40 (1:2:2) · ×0.30 (1:5:5).

검산: 하루 2회 성실 급여 → 평형 4~8(순함). 하루 방치 → ≈37(새콤). 이틀 → 60+(시큼).
한 번 놓친 게 체감되고, 되돌리기는 급여 2~3회로 쉽다.

냄새 구간(관찰 카드 문구): 고소한 밀가루(0~15) / 요거트 새콤(15~35) / 식초 기운(35~60) /
코 찡한 시큼(60~85) / 아세톤 기미(85+, 실제 현상).

### 3-6. maturity 적립

급여가 다음을 모두 만족할 때 +1: ① 직전 급여에서 **유효 6h 이상** 경과(연타 무효) ② 급여 시점 phase가
활발 또는 배고픔(시큼·휴면 중 급여는 회복만 되고 미적립). 하루 자연 상한 2사이클.

### 3-7. 부활 의식 (2세션 의식이 정본)

1. 실온 전제 — 냉장 상태면 "실온에 두고 밥 주세요" 먼저 안내 (실제 관행).
2. 급여 1회 → `reviveProgress = 1`, "12시간쯤 뒤에 다시 밥 주세요".
3. 유효 8h 이후 재급여 → `reviveProgress = 2` → 활발 복귀. 너무 이른 급여는 카운트만 안 될 뿐 무해(코지).
4. **maturity 전부 보존**(이름·도감은 sim 밖 소유라 애초에 영향 없음) — 르방은 기억을 잃지 않는다.
5. **반점·확산 단계(곰팡이 예고 중)의 급여도 같은 1회차로 작동한다** — 급여가 유효시간을 리셋하므로
   그대로 "걷어내고 새 밥"이 된다(§3-4-1). 곰팡이 진행 중에도 회피할 수 있다.

연출(VISUAL.md §4-3): 따라내기→밥은 각 급여에, "지켜보기" 줌인은 2번째 급여에만.

### 3-8. 시계 방어

- **역행**: `now < lastSimulatedAt − 5분`이면 저장된 **모든 타임스탬프**(createdAt·lastFedAt·lastSimulatedAt·
  lastDiscardBakeAt·collection.firstAt·flake.madeAt(있다면), 향후 필드 포함)를 delta만큼 당겨 **상대 간격 보존 재정박**.
  닫힌 함수 모델의 필수 규칙 — 나이 음수·단계 퇴행·크래시 전부 불가. 알림 전량 재예약.
- **미래 점프**: 정직한 catch-up (실제 르방도 시간이 흐르면 그렇게 된다 — 막지 않는다).
- **catch-up 상한 60일**: 실온에서는 곰팡이 종착(≤15일, §3-4-1)과 산미 포화가 고정점이라 그 이상은
  상태 불변 — 안전벨트. 곰팡이 판정 자체는 파생이라 이 캡과 무관하며, 캡은 acidity 적분에만 걸린다.
- **자정·DST**: epoch 차이만 쓰므로 특수 처리 자체가 없음. 로컬 시각은 알림 클램프에만.

## 4. 성장 단계

게이트 = `max(요구 사이클, 요구 일수)` — 둘 다 충족해야 승급.

| 단계 | 이름 | 조건 | 해금 |
|---|---|---|---|
| 0 | 갓 반죽 | 생성 | 온보딩. **D2 가짜 부풀기** 이벤트: 크게 부풀고 "곧 조용해져요. 정상이에요" |
| 1 | 잠잠기 | 3사이클·3일 | 침묵기(부피 표현 ×0.3). "이 시기는 원래 조용해요" |
| 2 | 첫 기포 | 7사이클·5일 | discard 레시피: 팬케이크·크래커 |
| 3 | 어린 르방 | 12사이클·8일 | 플랫브레드·포카치아·스콘, 1:2:2, **냉장 보관 해금** |
| 4 | 성숙 르방 | 21사이클·15일 | 식빵·바게트·깜빠뉴, 1:5:5 |
| 5 | 노포 | 45사이클·30일 | 호밀빵·통밀 깜빠뉴, **병 이름표(label)** |

### 6-2. 빵 레시피 (보관 통 소모 + 판정) — 2026-08-25 통 경제 개정

| 레시피 | 원가 | 산미 선호 | 엄격도 | 해금 |
|---|---|---|---|---|
| 플랫브레드 | 30g | 0~60 | 관대 | 3단계 |
| 포카치아 | 50g | 0~40 | 관대 | 3단계 |
| 식빵 | 80g | 0~30 | 보통 | 4단계 |
| 바게트 | 60g | 10~35 | 엄격 | 4단계 |
| 깜빠뉴 | 100g | 15~45 | 엄격 | 4단계 |
| 호밀빵 | 80g | **40~75** | 보통 | 5단계 |
| 통밀 깜빠뉴 | 120g | 20~50 | 엄격 | 5단계 |

**원가의 출처가 바뀌었다** — v1은 병 속 mass를 직접 깎았다. 이제 원가는 **보관 통**(`shared.pantry`,
집 전역, §5 "떼어내기"로만 채워진다)에서 나가고, 르방이의 mass는 굽기로 **전혀 변하지 않는다**.

- **표시(개정 2026-08-25)**: 우상단 보관 통(`.pantry-jar`, §5)의 잔량은 숫자가 아니라 **수위**로 읽힌다 —
  정확한 g 값은 `aria-label`에만 남는다. **병 아래 힌트 문구는 삭제**(개정 2026-08-26 — 항아리가
  물건으로 놓여 있으면 눌러본다. "이게 뭐냐"는 탭 응답과 설명서(`?`)가 답한다).
  병은 잠겨 있어도 항상 눌리고, 못 뗄 땐 이유와 남은 시간을 토스트로 말한다(§5 떼어내기).
- **게이트**: 단계만(`canBakeBread`는 stage만 본다) + 통 잔량 ≥ 원가(`gameStore.pantryGate`가 사전
  차단). 단계 게이트는 sim 소관, 통 게이트는 store 소관 — sim은 전역 통을 모른다(순수 유지,
  ARCHITECTURE §2). 통이 부족해도 **빵 시트는 열린다**(개정 2026-09-03 — 원가와 부족량이 시트 머리에
  보이는 게 진입 차단보다 낫다) — `굽기`를 누르면 "보관해둔 르방이 Ng 필요해요" 토스트로 막는다.
  이 빵을 구우면 통이 정확히 0이 되는 조합은 굽기 직전 확인 팝업(중앙 팝업)을 한 번 더
  거친다 — 취소하면 통·mass 둘 다 무차감.
- **씨앗 불가침이 더 강해졌다**: v1은 `mass ≥ 비용 + 60g`로 씨앗 60g에 여유를 남겨 굽기가 침범하지
  못하게 막았다. 지금은 굽기가 mass를 아예 건드리지 않으므로 그 여유 계산 자체가 필요 없다 —
  **어떤 액션도 르방이를 죽일 수 없다는 물리 보장**(죽음은 오직 오랜 방치(곰팡이) 하나뿐)이 마진이
  아니라 구조로 성립한다.
- **판정**: `점수 = 0.6 × activity(굽는 순간, 지금 활성 르방 기준) + 0.4 × 산미적합도`. 적합도 = 선호
  범위 안 1.0, 벗어난 만큼 감점(관대/보통/엄격 = 감점 기울기).
- **품질 세탁은 의도적으로 열려 있다**: 통이 전역이라 시큼한 르방 A에서 뗀 g이 피크에 든 르방 B로
  구워질 수 있다 — 등급은 굽는 **순간의 활성 르방**만 본다. "통은 재고(양)이고, 등급은 오늘 이
  르방이의 발효력(질)"이라는 프레이밍이 이걸 버그가 아니라 설계로 만든다: 여러 병을 돌보다 컨디션
  좋은 병으로 굽는 실제 제빵 습관과도 맞는다(의도적 이탈 — implementation-notes 2026-08-25 참조).
- **밀가루 친화**(2026-08-24, §3-1-1): 호밀빵×호밀 가루·통밀 깜빠뉴×통밀 가루면 적합도 +0.15(클램프 1.0).
  다른 레시피는 flour 무관 — 친화는 `flourAffinity` 데이터가 결정.
- **등급**: ≥0.85 "최고예요" / ≥0.6 "잘 구웠어요" / 그 외 "조금 납작해요. 그래도 맛있어요" — **실패 없음**.
- **호밀빵 = 시큼의 구원**: 방치돼 시어진 르방이 오히려 적기 (실제 호밀 사워도우가 그렇다).
- **커밋은 연출 시작 시** (`flags.pendingBake`에 기록) — 연출 중 강제종료해도 결과 유실 없음,
  재실행 시 미표시 결과 카드 재노출.
- **새 리듬 — 급여가 빌드, 피크가 떼기 창, 통이 굽기 창**: 급여로 mass를 불리고(1:2:2→300g,
  1:5:5→440g), 피크에서 씨앗 60g만 남기고 떼어(§5 "떼어내기") 통에 옮긴다. 게이트가 유효시간(마지막
  급여 후 6h)이라 피크를 정확히 못 맞춰도 나중에 뗄 수 있다 — 통은 g만 기억하고 그램을 뗀 순간의
  활성도는 기억하지 않는다. 굽기는 통 잔량만 있으면 아무 때나 가능하다.

**빵 시트**(중앙 팝업의 시트형 = 본문 스크롤·footer 고정, `modal.ts footer` 옵션):
- 머리: 큰 아트 · 이름 · 맛 · **`르방 100g 필요 · 보관 320g`**(모자라면 `· 100g 모자라요`, 정보 톤) · 등급·N번 · `변형 3/16`.
- **재료 넣기 = 4열 칩** — `기본` 칩 + **이 빵에 넣을 수 있는 재료 전부**(호환 규칙 `rulesForBase`에서 파생, 보유 무관):
  보유 = 또렷 + 수량 / 미보유 = 옅게(**이름은 보인다** — 무엇이 필요한지 여기서 읽힌다, 탭하면 교환소 안내) /
  발견한 변형이 있으면 ✓. 형태가 2개 이상인 재료는 칩 바로 아래 형태 행이 펼쳐진다(발견 ✓·`N번 만들었어요` / 미발견 `1개를 넣어요`).

  원자 해금·결과 쇼케이스는 §6-2·§6-4 그대로. **상세 화면(push)은 여전히 없다** — 시트 한 겹.
- **도감은 시트 안에 산다**: 변형 도감 = 칩의 ✓와 형태 행. 별도 "도감-빵" 뷰·?-실루엣 변형 카드 170장은 없다. 미발견 변형에
  필요한 재료 이름을 밝히는 근거: 교환소가 이미 30종을 이름째 보여준다.

**재료 그리드(30장)**: 아트 + 이름 + 우상단 **수량 pill**(`딸기 · 9개` 텍스트 폐지). "밝혀짐" 판정 = 보유 > 0 이거나 그 재료를 쓴
발견 변형이 하나라도 있으면 — 그 전엔 ?-실루엣(탭 = 힌트 토스트). 상단 가루 배너(§6-5)는 이 탭에만.

### 6-5. 무료 경제 (확장기획 §9 — Phase 7, 2026-08-25 신설)

광고·결제 이전에 바닥을 먼저 깐다. **광고는 나중에 "가속"만 판다** — 도달 자체는 무료로 열린다.

- **재화 2종뿐**: 재료 + **교환 가루**. 유료 젬 없음, 만료 없음, 랜덤 없음.
  원하는 재료를 정가로 사는 구조라 도박·불운이 게임에 들어오지 않는다.
- **잔액은 저장하지 않는다** (§1 닫힌 함수 모델): 가루 = 누적 획득 − 누적 사용이고,
  누적 획득은 카운터·도감의 함수(`store/economy.ts`). 이중 지급이 구조적으로 불가능하고,
  타임스탬프가 없어 시계 조작 면역 + §3-8 재정박 목록과 무관하다.
- 저장은 `shared.economy` — feeds·bakes·stageMax·exchanged·spent·gifted. 전부 단조 증가.
  키 부재 = 0(무버전 착륙, flour·inventory와 동일 — OTA 롤백 안전).

| 획득 경로 | 보상 | 비고 |
|---|---|---|
| 첫 재료 선물 | 재료 1개 (30종 중 **선택**) | 1회. 신규는 창조 의식 직후, 기존 저장본은 부팅 시 권함 |
| 누적 급여 10회마다 | 가루 12 | **무한 반복** — 무료 회복이 상존하는 자리 |
| 누적 굽기 5회마다 | 가루 12 | 무한 반복 |
| 성장 단계 최초 도달 | 단계당 가루 12 | **집(계정) 최고 기록** 기준 — 새 르방으로 재수령 불가 |
| 베이스 레시피 최초 완성 | 종류당 가루 12 | 도감에서 파생 (변형 키는 세지 않는다) |

  이득이지만 사고팔기를 반복해 가루를 불릴 수는 없다.
- **소프트캡 9**: 재료는 종류당 9개까지. 초과 지급분은 자동으로 가루가 된다(버려지지 않는다).
  캡에 도달한 종류는 구매가 거절된다 — 가루는 차감되지 않는다.
- **미션에 실패가 없다**: 기한·연속 기록·리셋이 존재하지 않는다. 누적 횟수만 쌓인다(§10 톤).
- **표면**: 레시피 화면 [재료] 탭 상단의 가루 배너 하나 — [재료 바꾸기](교환소)·[가루 모으기](미션).
  교환소(개정 2026-09-03, 시트형)는 잔액을 **머리**에 두고 재료 30종을 **4열 칩**으로 보여준다(이전 판은 30행 × 버튼 2 =
  60버튼, 잔액이 맨 아래) — 칩을 고르면 footer에 `{재료} · N개 있어요` + [가루 12개로 가져오기] [가루 4개로 바꾸기].
  잠금은 `.is-locked`(탭하면 이유 토스트). 광고 배송 행(§6-6)은 머리 아래. 재료 탭의 ?-실루엣은 "만나 본 기록"이라 축이 다르다.
- **처음 얻는 재료(0→1)는 획득 연출**(§5 표 "획득 연출")이 "새로 열린 빵 N종"까지 보여준다 — 선물·구매·광고 배송 공통.
- **수용 기준(§16)**: 광고 0으로 변형 **160종** 전부 도달 가능(2026-08-26 재료 30종 확장 반영 —
  이전 판은 12종·72종, 그 이전은 40종) — `tests/economy.test.ts`가 실제 급여·떼기·구매·굽기 루프로
  검증한다(선물 1 + 구매 159 = 가루 **1908**). 변형만 노리는 최단 루프는 **급여 1231회**
  (하루 2회 기준 ≈616일)이고, 같은 테스트가 상한 `MAX_FEEDS=1601`(실측×1.3)으로 실측 강제한다.
  - ★**상한을 그냥 올리지 않고 다시 쟀다.** 상한의 정의가 "실측의 약 1.3배"라서, 안 재고 올리면
    그 숫자가 무엇의 1.3배인지 아무도 모르게 된다. 이전 판(72종)의 실측은 521회였다.
  - ★**페이싱 상수는 그대로 두는 게 사용자 확정이다**(2026-08-26). 616일이 길지만 수용 기준은
    "닿는가"이고 닿는다. **가속은 과금이 판다** — 확장기획 §10의 보상형 광고·IAP가 그 경로이고,
    **아직 미구현**이라 현재는 파는 가속이 없다.
  - 병목은 여전히 재료(가루) 쪽이다 — 사이클당 그램 예산이 그 주기에 굽는 양보다 넉넉해 그램은
    병목이 아니다. 핵심 레시피 10종은 재료를 요구하지 않으므로 유료·광고 전용 레시피는 0개다.

### 6-6. 보상형 광고 (확장기획 §10 — 2026-08-30 신설)

  잡은 결함: 웹 빌드 교환소에 광고 행이 그대로 떴다).

| 1′ | 냉장 중 — 슬롯 1이 **주간 반복 예약**(`every:'week'`)으로 전환 | "일주일이 지났어요. 밥 줄 때가 됐어요" |
| 2 | 휴면 진입 예측 시각 | "르방이 깊이 잠들었어요. 잊지 말고 깨워 주세요" |
| 3 | 곰팡이 예고(`moldWarn`) — 반점이 미래면 반점 시각, 아니면 확산 시각 | "르방이 표면에 반점이 보여요. 아직 늦지 않았어요" |
| 4 | 피크 밴드 시작 시각(`peak`) — 조용시간으로 민 시각이 밴드를 지나면 **스킵**(클램프 금지: "한창"이 거짓말이 된다). **기본 on**(2026-09-03 승격 — 이전 판 기본 off. 기존 저장본에 남은 off는 존중) | "한창 부풀어 있어요. 지금 굽거나 떼어 두기 좋아요" |
| 5 | 시큼 진입 예측 시각 = 배고픔 + 22h(`sour`, 신설 2026-09-03). 밥 D1 뒤 두 번째 손짓 — 사실 + 위로 한 문장 | "조금 시큼해졌어요. 밥을 주면 금방 돌아와요" |
| 6 | 성장 승급 예정 시각(`stageUp`, 신설) — 요구 사이클은 채웠고 **일수만 남았을 때** `createdAt + 요구일`. 사이클이 남았으면 예측 불가라 안 심는다 | "{단계} 단계가 되었어요" |
| 7 | 첫 주 D2 가짜 부풀기 `createdAt + 24h`(`firstWeek`, 신설, 0단계에만). "매일 열어볼 이유"(§4)를 첫날 밖에서도 준다 | "크게 부풀었어요. 곧 조용해질 거예요, 정상이에요" |

슬롯 4~7은 각각 설정 토글(`notifyPeak/notifySour/notifyStage/notifyFirstWeek`, 무버전 추가 키, 기본 on)이고 **활발(실온·창가) 분기에만** 심는다 —
냉장·휴면·부활·곰팡이 분기는 아래 규칙 그대로.

휴면 분기: `dormant && reviveProgress=0` → 슬롯 1 취소(침묵 정합) /
`reviveProgress=1` → 슬롯 1을 유효 8h의 wall 시각(위치 앵커 회계 — 냉장 이동 반영, 2026-08-30 정정)으로 예약, "다시 밥 줄 시간이에요".

**슬롯 3 규칙**: 휴면 후엔 곰팡이 예고 1건(슬롯 3)만 남기고 침묵한다. **사망 시점·사망 후 알림은 0건** —
죽음을 푸시로 통지하지 않는다. fridge·부활 의식 분기를 제외한 모든 분기(활발 포함)에서 예약된다 — 재계획은
액션 시에만 일어나므로, 완전 방치자의 마지막 예약은 마지막 액션 직후에 정해져야 하기 때문이다. 냉장 분기는
슬롯 3을 포함하지 않는다(냉장은 곰팡이까지 ≈175일 + 주간 반복이 이미 재관여를 담당) — 한계 수용: 앱을 영영
안 열면 주간 반복이 사망 후에도 계속 발화할 수 있다(재계획 기회가 없으면 취소 불가).

완전 방치 검산: 총 **4건**(밥 D1·시큼 D2·휴면 D5·곰팡이 D7) 후 침묵(이전 판 3건 + 시큼).

- 조용시간 기본 22~08시, **설정에서 시 단위 변경 가능**(개정 2026-08-30 — 교대근무 대응). 창이 끝나는 시각으로 민다. start=end면 조용시간 없음. 낮 창(start<end)도 허용.
- **하루 최대 2건은 코드가 강제한다**(`capPerDay`, 2026-09-03 — 이전 판은 원칙만 있고 강제 로직이 없었다): 같은 로컬 날짜에
  3건 이상 몰리면 우선순위(곰팡이 > 휴면 > 부활 > 밥 > 시큼 > 피크 > 성장 > 첫 주) 낮은 것부터 드롭. 주간 반복 슬롯은 집계에서 제외.
  멀티 르방 병합 뒤에도 한 번 더 적용.
- Android 채널 2분할(2026-08-30): 케어(밥·냉장·부활·피크·시큼·성장·첫 주, importance DEFAULT) / 중요 알림(반점·깊은 잠, importance HIGH) — 시스템 설정에서 따로 조절 가능.
- inexact 알람(SCHEDULE_EXACT_ALARM 회피). 문구도 "쯤" 뉘앙스로 정합.
- 죄책감 유발 금지. 스팸 금지.
- **알림 탭 딥링크**(2026-09-03): 밥·냉장 주간·부활 2회차·시큼 = 홈 + **밥 모달 자동 오픈** / 피크 = 레시피 탭 / 나머지 = 홈.
  콜드 스타트로 열려 브리핑·곰팡이 모달이 먼저 떠 있으면 그것들이 닫힌 뒤 실행. 온보딩 전엔 무시. 알림 본문 1줄 = 르방 이름(멀티 르방에서 누구 얘긴지).
- **설정 표면**(2026-09-03): 설정 → `알림` 행 → 하위 모달 = 마스터 토글(`알림 받기`) + 항목 4개(한창때·시큼해질 때·단계가 오를 때·첫 주 안내,
  마스터가 꺼져 있으면 `.is-locked`) + 방해 없는 시간 + 권한 안내 행(거부 상태면 "시스템 설정에서 켤 수 있어요").
- 권한 상태기계: 온보딩 말미(첫 밥 후, 가치를 본 뒤) 요청 / 거부해도 전 기능 정상 /
  설정에 "시스템 설정에서 켤 수 있어요"(코어 플러그인엔 앱 설정 딥링크가 없어 안내 문구뿐 — `notifications.ts`).

## 8. 일일 리듬 — 3분 세션

**아침 (2분 30초)**: 열기 → catch-up 스냅(어젯밤 밥의 결과가 이미 반영돼 있음) → 병 탭 관찰
("요거트처럼 새콤한 냄새. 마지막 밥 11시간 전") → 1:2:2 밥(저녁 굽기 계획) → 팬케이크 → 닫기.

**저녁 (3분)**: 열기 → 피크 근처로 한껏 부푼 반죽(개정 2026-08-24: 고무줄 마커 제거 반영) → 띄워보기 "지금 굽기 좋아요" →
깜빠뉴 100g → "잘 구웠어요" → 1:1:1 밥 → 닫기.

**바쁜 주(냉장)**: 일요일 밥+냉장 → 주 1회 알림 → 꺼내서 실온·밥 → 다시 냉장. 주 1회 1분.

### 8-1. 복귀 브리핑

`briefing.ts`의 순수 함수 `deriveBriefing(state, from, to): BriefingKey[]`가 부재(wall-clock) **8h 이상**일 때
"그동안 있었던 일"을 중앙 모달에 시간순 카드로 보여준다. `BriefingKey` 8종: `peaked`(한껏 부풀었다가 가라앉음) ·
`becameHungry`(배가 고파짐) · `hoochAppeared`(표면에 액체) · `becameSour`(시큼해짐) · `wentDormant`(깊은 잠) ·
`moldSpotted`(반점) · `moldSpread`(반점 번짐) · `moldDied`(곰팡이). 부활 의식 1회차 대기 중(`reviveProgress=1`)이거나
시계가 역행한 직후에는 빈 배열 — 의식과 무관한 오보를 막는다.

### 8-2. 진단 순간

관찰 카드(§5 관찰 계약 — "정보 + 응답 1개까지" — 유지)에 새 신호 3종이 더해진다: **kahm**(창가 위치 + 시큼
구간에서 파생 — 주름진 흰 막, 무해), **잿빛**(휴면 중 겉모습만 그렇다는 안내), **아세톤 기미**(냄새 구간
85+, §3-5). 이 3종은 정보만 제공하고 대응은 카드의 응답 슬롯(말려두기)이 아니라 기존 액션에 매핑된다 —
걷어내고 밥 = 홈 밥주기 버튼, 폐기·플레이크 복원 = 사망 모달 전용. 조작 1개 상한을 넘기지 않는다.

## 9. 온보딩 (첫 실행)

저장 없음 → **창조 의식**: 밀가루+물 섞기(드래그로 젓기 — 기존 wobble 인터랙션이 첫 터치포인트) →
`createdAt` 기록, 초기 상태 생성 → 0단계 스크립트 주간이 튜토리얼을 겸한다 →
첫 밥 직후 알림 권한 요청. 완료 플래그는 `flags.onboarded`.

의식 직후 **첫 재료 선물**(§6-5) — 30종 중 하나를 고른다. 고르면 변형 하나를 바로 열 수 있다.
기존 저장본(온보딩을 이미 지난 사용자)은 부팅 브리핑 뒤에 같은 모달을 권하고, 놓쳐도
재료 탭 배너에서 언제든 받는다 (`economy.gifted`).

## 10. 문구 원칙

- 전 문구 `src/ui/copy.ts` 한 파일 — 전수 감수 가능.
- 담백한 한 문장. 시스템어·내부 용어(활성도, phase, catch-up, 스키마) 절대 노출 금지.
- 죄책감 유발 금지, 느낌표·의성어 남발 금지.
- 죽음 문구 = 사실 서술 + 위로 한 문장. 원인 추궁·"~했더라면" 화법 금지.
- 예: 저장 실패 → "기록을 못 남겼어요. 다시 해볼게요" / 배고픔 → "밥 먹을 시간이에요" /
  휴면 → "깊이 잠들어 있어요" / 부활 성공 → "다시 숨쉬기 시작했어요" /
  방치 복귀 → "괜찮아요. 르방은 잘 버텨요."
