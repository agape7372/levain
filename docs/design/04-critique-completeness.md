# 르방이 설계 3종 완전성 감사 — 출시를 막는 구멍 12건 (심각도 순)

## 1. [블로커] 시뮬레이션 정본이 두 벌이다 — 패러다임·스키마·수치가 문서마다 다름

**무엇**: 시뮬 문서(§1~2)는 "타임스탬프+느린 누적값만 저장, 나머지는 닫힌 함수 파생, O(1) catch-up" 모델. 아키텍처 문서(§2)는 "60초 고정 스텝 적분 + `remainderMs` + 가산성" 모델. 상태 필드도 전부 어긋난다: `acidity 0~100` vs `sourness 0~1`, `maturity`(사이클 int) vs `maturityMs`, `location: room/window/fridge` vs `temperature: cold/room/warm`, 시뮬 문서의 `feedRatio`·`mass`·`discard`·`unlockedRatios`·`collection`이 아키텍처 `SimState`에 전무. catch-up 상한도 60일(시뮬 §2-1) vs 90일(아키 §2)로 충돌. 결정적으로 **시계 역행 정책이 패러다임에 결합**돼 있다: 아키의 `dt<0 → 0, lastSimAt=now`는 스텝 모델에서만 안전하고, 닫힌 함수 모델에선 `lastFedAt`이 미래에 남아 activity·phase·volume이 음수 경과시간으로 계산된다 — 시뮬 §8의 "전 타임스탬프 재정박"은 그래서 존재한다.
**왜 막나**: M1(sim 코어) 착수 자체가 불가능하고, additivity 테스트·마이그레이션 픽스처·notifyPlan까지 전부 어느 스키마 기준인지 정의 불능.
**보완**: 시뮬 문서 모델을 정본으로 선언(콘텐츠 전부 — 비율·mass·단계 — 가 거기 산다. O(1) catch-up이 rAF 금지 조건과도 정합). 아키 문서의 **계약**(순수성, Clock 주입, FakeClock, 복구 사다리, 레이어링)만 그 위에 재기술. `remainderMs`·`STEP_MS`·`rngSeed(스텝 전진)`는 사장 필드로 삭제, 시계 역행은 재정박 방식으로 단일화, 상한은 60일로 통일. additivity 테스트는 닫힌 함수 모델에선 "파생값이 저장 시점과 무관"을 검증하는 형태로 바꿔 유지.

## 2. [블로커] 게임 규칙·화면 인벤토리 모순 4건 — 콘텐츠 정의가 문서마다 다름

**무엇**: ① **젓기**: 시뮬 §3 "시뮬레이션 효과 없음(배고픔 리셋하면 결정 1 위반)" vs 아키 §2 `stir // 소량 활력, 쿨다운` — 정면 충돌. ② **부활 의식**: 시뮬 §2-5 "급여 2회, 유효 8h 간격"(2세션짜리 의식) vs 비주얼 §3-3 "따라내기→밥→지켜보기 ~5초 원세션 완결, 즉시 크림색 회복". ③ **이름**: 아키 온보딩 "이름 짓기"+`name`/`rename` 액션+설정의 이름 변경 vs 시뮬 저장 스키마에 name 없음+5단계 보상이 "병 이름표". ④ **화면 누락**: 시뮬 §3의 핵심 UX인 띄워보기(float test)·관찰 카드(병 탭)가 아키 화면 목록·Action 타입에 없고, 탭 구조도 4탭(아키 §5) vs 2~3탭(비주얼 §6-3)으로 갈린다.
**왜 막나**: M4 수용 기준("온보딩→홈 풀 루프")이 어느 정의가 이기느냐에 따라 달라진다 — 모순이 마일스톤 판정 기준까지 오염시킨다.
**보완**: 젓기=코스메틱(시뮬 문서 승 — 근거가 명시돼 있음), 부활=2세션 정본으로 하되 비주얼 §3-3 연출을 "각 급여 1회분"으로 재배치(3단계 지켜보기는 2번째 급여에만), 이름=5단계 보상으로 단일화(무캐릭터 톤과도 정합 — 온보딩 이름 짓기·rename 삭제), 띄워보기·관찰카드를 아키 화면 목록과 Action에 추가, 탭은 4탭으로 확정.

## 3. [블로커] 카메라·병 스코프 모순 — 비주얼의 P1이 마일스톤에 없다

**무엇**: 아키 §0은 "탑다운 구도 살린다(viewH 3.4/bottom -1.52 계승)", 병 업그레이드는 "M7 옵션". 비주얼 §1은 탑다운을 **교체**(55° 틸트, viewH 4.2) + 유리병 3패스 + 고무줄 마커 + hooch 층 + 천 덮개를 설계하고, 부록에서 이걸 우선순위 1("성장이 보이는 순간 게임이 성립")로 못박았다. 마일스톤 표(M0~M7)에는 틸트·병·고무줄 작업이 앉을 행이 아예 없다 — M0 수용 기준은 "픽셀 동급 이식"이라 오히려 금지한다.
**왜 막나**: 부피=성장 피드백은 시뮬 설계(volume, uFillY, 고무줄=정본 표시 장치)의 핵심 출력인데, 탑다운에선 표현 불가(비주얼 §1-1의 탈락 근거). 스코프 미조정 시 M3에서 일정이 터지거나 성장이 안 보이는 게임이 나온다.
**보완**: 비주얼 §1을 정본으로 채택하고 마일스톤 개정 — M0은 "픽셀 동급"에서 "셰이더·팔레트 동급"으로 완화, M3을 "카메라 틸트+병 3패스+고무줄+uFillY"(비주얼 부록 1·2번)로 재정의, hooch·천 덮개는 M5 근처로.

## 4. [높음] Android 하드웨어 뒤로가기 — 세 문서 모두 0건

**무엇**: `@capacitor/app`의 `backButton` 리스너, 모달/스택 화면/굽기 연출 중의 백 처리, 루트에서의 동작이 어디에도 없다. URL 없는 커스텀 스택 라우터(아키 `ui/router`)라 리스너 미등록 시 하드웨어 백 = 어디서든 즉시 앱 이탈.
**왜 막나**: 레시피→굽기 연출 5.5초 중 백 누르면 앱이 꺼지는 앱은 내부테스트에서 바로 걸리는 UX 결함이고, Android 사용자의 제1 내비게이션 수단이다.
**보완**: `backButton` 리스너 계약을 아키 §5에 추가 — 열린 모달 있으면 닫기 → `router` depth>0면 `back()` → 루트면 `App.minimizeApp()`(종료 아님 — 다마고치는 백그라운드 생존이 자연스럽다). 연출 중엔 백 = 연출 스킵. Android 14+ predictive back 호환은 M6 실기기 검증 항목으로 등재.

## 5. [높음] 알림 설계 불일치 + 권한 영구 거부 플로우 구멍

**무엇**: 시뮬 §7은 알림 6종(밥·무응답+24h·시큼·휴면·냉장 주1회·피크 옵트인)+조용시간 클램프. 아키 §6은 고정 슬롯 **3개**(밥/배고픔/휴면)만 정의하고 조용시간·냉장 반복·피크 알림이 `notifyPlan` 반환 타입에 없다. 냉장 주1회는 "다음 주 열 때 재예약" 전략으론 앱을 안 열면 영영 안 울린다. 권한 쪽은 "온보딩 말미 요청"뿐 — Android 13+에서 2회 거부 시 영구 거부되는 상태, 설정 토글 on인데 OS 권한 off인 불일치 상태의 처리가 없다.
**왜 막나**: 알림은 이 장르의 리텐션 척추다. 냉장 유지 모드(주 1회 세션)는 알림이 안 오면 게임이 끝난다.
**보완**: 슬롯을 6개 고정 id로 확장, 냉장 주간은 `every: 'week'` 반복 예약으로 앱 미실행에도 발화. `planNotifications(state, quietHours)`로 조용시간을 인자 주입(순수성 유지). 권한 상태기계 명문화: 미결정→온보딩 말미 요청 / 거부→토글 off + 설정 화면에서 "시스템 설정에서 켤 수 있어요" + `openSettings()` 딥링크.

## 6. [높음] settings·온보딩 플래그·도감의 저장 위치 미정 — 복구 사다리 밖의 데이터

**무엇**: 아키 `SaveEnvelope`는 `SimState`만 감싼다. 그런데 시뮬 §1-2의 `settings`(조용시간·notifyEnabled), 비주얼 §4-2/§5-1의 햅틱·muted("저장 스키마에 포함"이라고만), 아키 §5의 온보딩 완료 플래그("저장에")가 `SimState`에 없다 — 저장 위치가 어느 문서에도 확정 안 됨. `schemaVersion` 위치도 시뮬은 state 안, 아키는 envelope 밖으로 충돌.
**왜 막나**: 스키마 밖 데이터는 복구 사다리·마이그레이션·미러의 보호를 못 받는다 — "저장 유실 0" 기준을 조용히 깬다. 출시 후 첫 스키마 변경 때 발견하면 늦다.
**보완**: `SaveEnvelope { schemaVersion, savedAt, sim, settings, flags: { onboarded } }`로 확정 — settings/flags를 sim 밖·envelope 안에 두면 sim 순수성과 복구 커버리지를 동시에 만족하고 schemaVersion 위치 충돌도 해소된다. migration 픽스처는 envelope 단위로 얼린다.

## 7. [높음] 기기 이전·재설치 시 세이브 소멸 — 백엔드 0의 대가가 미설계

**무엇**: 설정 화면은 "알림·이름 변경·데이터 초기화"뿐. 세이브 내보내기/가져오기가 없고, Android Auto Backup(`allowBackup`)과 WebView localStorage·Preferences 미러의 상호작용은 언급조차 없다(동작 미정의·미검증 영역).
**왜 막나**: 30일 키운 5단계 노포가 폰 교체·앱 재설치로 증발한다 — "영구 사망 없음" 계약이 기기 경계에서 깨지는 셈이고, 다마고치 장르에서 최상급 별점 1점 사유다.
**보완**: 설정에 "기록 내보내기/불러오기" 추가 — envelope JSON을 파일로 저장/읽기(`@capacitor/filesystem` + 공유 시트, 웹은 다운로드). `allowBackup` 정책을 명시 결정하고(켜면 Preferences 미러가 재설치 복원을 공짜로 줄 가능성 — 단 검증 필수), 재설치→복원 상태를 M6 QA에 항목화.

## 8. [중간] mass 산수 오류 + 초기값·discard 오버플로 미정의

**무엇**: 씨앗 60g 규칙으로 검산하면 1:1:1=180g ✓, 1:2:2=300g ✓인데 1:5:5는 60×(1+5+5)=**660g ≠ 표의 480g**(시뮬 §2-4, mass 상한 480도 연동 오류). 창조 의식은 `createdAt`만 기록 — 최초 mass가 미정. discard는 상한 300g인데 1:5:5 급여 한 번에 420g이 들어온다 — 초과분 규칙(클램프? 버림? UI 안내?)이 없다.
**왜 막나**: mass는 굽기 게이트(`mass ≥ 비용+60`)의 축 — 수치가 안 맞으면 경제 밸런스와 경계 테스트를 작성할 수 없다.
**보완**: 1:5:5를 660g으로 정정하거나 씨앗을 비율별 가변(480÷11≈44g)으로 재정의 — 하나를 골라 표·상한·검산을 재계산. 초기 mass(제안: 60g)와 discard 초과 시 "통이 가득 차면 넘치는 만큼 사라져요" 클램프+담백한 안내를 명문화.

## 9. [중간] sim→render 계약이 3중 정의 — 같은 이음새에 인터페이스가 세 벌

**무엇**: 시뮬 §1-3 `snapshot`(phase·activity·volume·smell·stage), 아키 §4 `VisualParams`(riseScale·sag·tint·bubbleAmount·breathe*), 비주얼 §2-1 `SimVisualState`(activity·hunger·sourness·dormancy·fill·hooch)→`RenderParams`. uniform 이름도 두 벌(uRise/uSag/uTint/uBubble vs uFillY/uColor/uBreatheAmp/uBubbleDensity/uCrust/uHoochAmt). `hooch`·`fill`이 sim 출력인지 render 파생인지 소속 미정.
**왜 막나**: M3에서 세 팀 분량의 문서가 서로 다른 함수를 구현하게 된다 — 이음새 버그는 "시각 오류 0" 기준을 직격.
**보완**: 단일 계약으로 통일: `deriveSnapshot(state, now) → Snapshot`(hooch·fill 포함 — sim이 물리량의 정본) → `toRenderParams(snap) → RenderParams`(비주얼 §2-2 uniform 표를 정본 채택, 아키 §4 이름 폐기). 이 두 함수만 vitest 대상.

## 10. [중간] 상태바·엣지투엣지 미설계 — 세이프에어리어가 하단만 있다

**무엇**: 비주얼 §6-3은 탭바 하단 `safe-area-inset-bottom`만 다룬다. `@capacitor/status-bar` 스타일(베이지 배경엔 어두운 아이콘 필수 — 기본 흰 아이콘은 비가시), 상태바 배경/오버레이 여부, 상단 inset, 그리고 **targetSdk 35(Android 15)의 강제 edge-to-edge**가 어느 문서에도 없다.
**왜 막나**: 첫 실행 화면 최상단에서 바로 보이는 시각 오류다 — "시각 완성도: 시각 오류 0" 기준과 정면충돌하고, Play 신규 앱은 targetSdk 35가 요구된다.
**보완**: M6 항목에 추가 — StatusBar `style: Dark`(어두운 아이콘)+오버레이 모드, 상단 HUD에 `env(safe-area-inset-top)`, edge-to-edge 대응을 펀치홀 기기 실기기 QA로. 스플래시 단색(#E8D9C4)과 상태바 색 연속성도 함께.

## 11. [중간] Play 내부테스트 제출물 체크리스트 부재

**무엇**: 아키 M6은 "서명 AAB·내부테스트 등록"까지만. 개인정보처리방침 URL(수집 0이어도 필수), Data Safety 폼, 콘텐츠 등급 설문, 스토어 등록정보(아이콘 512·피처 그래픽·스크린샷 2장+)가 어느 문서에도 없다.
**왜 막나**: 전부 없으면 내부테스트 트랙에 올리는 것 자체가 막힌다 — M6 완료 판정 불가.

## 12. [중간] QA 시나리오 누락 묶음 — 체크리스트가 해피패스에 치우침

**무엇**: 아키 §7 수동 QA에 다음이 없다: ① 하드웨어 백 전수 시나리오(모달·연출 중·루트) ② 알림 권한 영구 거부 → 설정 딥링크 왕복 ③ Doze/절전에서 inexact 알람 지연 체감(수 분~수십 분 — 문구가 "정각" 뉘앙스면 어긋남) ④ 굽기 연출 5.5초 중 강제종료 — harvest 커밋 시점(연출 전 커밋이면 빵은 기록됐는데 유저는 못 봄) 및 확인 버튼 연타 가드 ⑤ 시계 역행 후 알림 재예약 검증(재정박과 짝) ⑥ 재설치 후 Auto Backup 복원 상태(발견 7과 짝) ⑦ OS 폰트 스케일 200%에서 레이아웃.
**왜 막나**: 릴리스 게이트가 이 목록인데, 실기기에서 실제로 터지는 유형(권한·절전·인터럽트)이 빠져 있으면 게이트가 통과를 보증하지 못한다.
**보완**: 7항을 §7 체크리스트에 추가하고, ④는 "harvest 커밋은 연출 시작 시 + 재실행 시 미표시 결과 카드 재노출" 규칙을 아키 §5 굽기 화면에 명문화.
