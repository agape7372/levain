# 르방이 — 게임 시뮬레이션·콘텐츠 설계

> 설계 전제: 시뮬레이션은 렌더러와 완전 분리된 순수 함수 코어(`advance`/`snapshot`), wall-clock 기반, 백엔드 0, 영구 사망 없음. 확정 결정 1~10을 모두 준수한다.

---

## 1. 상태 모델

### 1-1. 설계 원칙: 저장하는 것과 계산하는 것을 가른다

저장(정본) 상태는 **타임스탬프와 느린 누적값만** 담는다. 활성도·부피·거품·냄새·배고픔 단계는 전부 `(지금 − 마지막 밥) × 온도 배율`의 닫힌 함수로 파생한다. 이 분리 덕에:

- 오프라인 catch-up이 O(1) — 틱 루프 불필요, rAF 누적 금지 조건 충족.
- 위치(온도)는 앱이 켜져 있을 때만 바뀌므로, 오프라인 구간은 항상 **단일 온도 배율 구간** — advance()가 변하는 온도를 적분할 일이 없다.

### 1-2. 저장 상태 (정본, localStorage + Capacitor Preferences 미러)

| 변수 | 타입/범위 | 단위 | 의미 |
|---|---|---|---|
| `schemaVersion` | int, 1부터 | — | 마이그레이션 사다리용 |
| `createdAt` | epoch ms | ms | 르방 탄생 시각. 성장 단계의 "최소 일수" 게이트에 사용 |
| `lastFedAt` | epoch ms | ms | 마지막 급여 시각. 활성 곡선의 원점 |
| `lastSimulatedAt` | epoch ms | ms | advance()가 마지막으로 반영한 시각. 시계 역행 방어 기준 |
| `feedRatio` | `'1:1:1' \| '1:2:2' \| '1:5:5'` | — | 마지막 급여 비율. 활성 곡선의 모양을 정한다 |
| `location` | `'room' \| 'window' \| 'fridge'` | — | 병 위치 = 온도 배율 |
| `acidity` | float 0~100 | 무차원 | 산미 누적. 냄새 문구·굽기 판정·연출 색조에 반영 |
| `maturity` | int 0~ | 사이클 | 건강 급여 사이클 누적 수. 성장 단계·해금의 축 |
| `mass` | int 60~480 | g | 병 속 르방 총량. 급여로 차오르고 굽기로 소모. 480은 1:5:5 결과의 설계 상한 |
| `discard` | int 0~300 | g | 덜어낸 반죽 통. discard 레시피의 재료 |
| `reviveProgress` | int 0~2 | 회 | 휴면 부활 의식 진행도 |
| `collection` | `{recipeId: {bestGrade, count, firstAt}}` | — | 도감 |
| `unlockedRatios` | 배열 | — | 해금된 급여 비율 |
| `settings` | `{quietStart: 22, quietEnd: 8, notifyEnabled}` | 시 | 알림 조용 시간 |

**저장하지 않는 것(과설계 금지)**: 활성도·부피·거품량·냄새·현재 단계(휴면 제외 전부 파생), 수화율(100% 고정 — 레시피 카드의 맛 설명에만 등장), 온도 이력(위치만 저장), 밥 이력 로그(도감 외 히스토리 없음).

### 1-3. 파생 상태 — `snapshot(state, now)`

렌더러·UI가 매 프레임 호출하는 순수 함수. 반환:

- `phase`: `active | hungry | sour | dormant` (유효 경과시간으로 판정)
- `activity` 0~1: 활성 곡선 값 → 셰이더 숨쉬기 진폭·기포 밀도
- `volume` 1.0~3.0: `1 + 2 × activity × stageFactor` → 반죽 스케일
- `smell`: 산미 구간 문구 (관찰 카드용)
- `nextFeedAt`, `peakAt`: 예측 시각 (UI 안내·알림 예약용)
- `stage` 0~5: 성장 단계 (maturity + 경과 일수)

## 2. 시뮬레이션 규칙 — `advance(state, nowMs)`

### 2-1. 계약

- 순수 함수: `Date.now()` 내부 호출 금지, 호출자가 now 주입. 같은 `(state, now)`에 멱등.
- `elapsed = max(0, now − lastSimulatedAt)` — 음수면 0 (시계 역행은 §8).
- 유효 경과 = `elapsed × tempMult(location)`. 오프라인 중 위치는 불변이므로 배율 하나로 충분.
- 단일 catch-up 상한 60일. 휴면+산미 포화가 고정점이므로 그 이상은 상태가 변하지 않는다 — 상한은 안전벨트.

### 2-2. 온도 배율표 — 모든 수치의 뿌리

| 위치 | 상정 온도 | 배율 | 의미 |
|---|---|---|---|
| 실온 | 24°C | ×1.0 | 기준. 하루 1~2회 급여 리듬 |
| 창가 | 27~28°C | ×1.3 | 서두를 때. 피크가 이르고 배고픔도 빠르다 |
| 냉장고 | 4°C | ×0.08 | 유지 모드. 주 1회 급여 |

**일관성 검산**: 배고픔 14h ÷ 0.08 ≈ 175h ≈ **7.3일** → "냉장 시 주 1회"가 같은 표에서 저절로 나온다. 피크 4.5~6h(실온)는 실제 르방의 "밥 후 4~8시간 피크" 범위 안.

### 2-3. 활성 곡선 (밥 이후 유효시간 h 기준, 1:1:1)

```
0h ───── 0.75h ───── 4.5h ══ 6h ───── 12h ───── 14h ───── 36h ───── 120h
  잠복기    상승(smoothstep)  피크      하강        배고픔      시큼       휴면
  0→0.15                    1.0       →0.25      표면 꺼짐   훅치 연출   회색빛
```

- 잠복기 0~45분: activity 0→0.15 (급여 직후 조용)
- 상승 45분~4.5h: smoothstep으로 1.0까지
- 피크 4.5~6h: activity 1.0 유지 (부피 2.5~3×)
- 하강 6~12h: 0.25까지 완만히
- 이후 배고픔 전이

### 2-4. 급여 비율 = 플레이어의 스케줄 도구

| 비율 | 피크(실온) | 배고픔 | 급여 후 mass | 리듬 |
|---|---|---|---|---|
| 1:1:1 (기본) | 4.5~6h | 14h | 180g | 하루 2회. 아침 밥 → 점심 피크 |
| 1:2:2 (해금) | 7~9h | 20h | 300g | 하루 1회. 아침 밥 → 저녁 피크 굽기 |
| 1:5:5 (해금) | 10~12h | 30h | 480g | 밤 밥 → 아침 피크. 실제 제빵사 패턴 |

새 상태 변수 0개로 깊이 추가 — 곡선의 시간축만 비율별로 늘어난다.

### 2-5. 상태 전이 (유효시간, 1:1:1 기준)

비율별로 이동하는 것은 배고픔 시점이고, 시큼·휴면은 **배고픔으로부터의 오프셋**으로 정의한다: 시큼 = 배고픔 +22h, 휴면 = 배고픔 +106h. (1:1:1이면 14h/36h/120h — 아래 수치 그대로. 큰 급여일수록 버퍼도 같이 밀려나 물리 논리가 유지된다.)

```
활발(active) ──14h──▶ 배고픔(hungry) ──36h──▶ 시큼(sour) ──120h──▶ 휴면(dormant)
     ▲                                                                │
     └───────────────── 부활 의식(급여 2회, 각 ≥8h 간격) ◀─────────────┘
```

- **배고픔**: 부피 1.1×로 꺼짐, 표면 주름. 급여하면 즉시 활발로.
- **시큼**: 48h부터 훅치(hooch, 회색 액체층) 연출. 급여 2~3회면 산미 회복.
- **휴면**: 기포 0, 색 바램. 급여해도 즉시 안 살아남 — 부활 의식 필요.
- **부활 의식**: 실온에서 진행한다("실온에 두고 밥 주세요" — 냉장 상태면 먼저 안내, 실제 관행과 동일). 휴면 중 급여 → `reviveProgress=1`, "12시간쯤 뒤에 다시 밥 주세요" 안내. 유효 8h 이후 재급여 → `reviveProgress=2` → 활발 복귀. 너무 이른 급여는 카운트만 안 될 뿐 해가 없다(코지). maturity는 보존 — 르방은 기억을 잃지 않는다.

### 2-6. 산미 누적·감소

누적(유효시간당): 활발 +0.3/h · 배고픔 +1.5/h · 시큼 +2.5/h · 휴면 +0.5/h.
급여 시 희석: ×0.55(1:1:1) · ×0.40(1:2:2) · ×0.30(1:5:5).

검산: 1:1:1 하루 2회 성실 급여 시 평형 산미 ≈ 4~8 (순한 상태 유지). 하루 방치 → ≈37(새콤), 이틀 → 60+(시큼). 복구는 급여 2~3회. 한 번 놓친 게 체감되고, 되돌리기는 쉽다.

산미 구간: 0~15 고소한 밀가루 냄새 / 15~35 요거트 같은 새콤함 / 35~60 식초 기운 / 60~85 코가 찡한 시큼함 / 85+ 아세톤 비슷한 냄새(실제 현상).

### 2-7. maturity(성숙 사이클) 적립 규칙

급여가 다음 조건을 모두 만족할 때 +1: ① 이전 급여에서 유효 6h 이상 경과(연타 방지) ② 급여 시점 phase가 활발 또는 배고픔(시큼·휴면 중 급여는 회복은 되지만 사이클 미적립). 하루 최대 2사이클이 자연 상한.

## 3. 플레이어 행동

| 행동 | 입력 UI | 효과 |
|---|---|---|
| **밥주기** | 메인 버튼 1개 → 시트에서 비율 선택(해금분만, 기본=최근 사용) | `lastFedAt=now`, 산미 희석, mass 재설정, 덜어낸 양(`mass−60g`)이 discard 통으로, maturity 판정. 연출: 덜어내기→가루·물 붓기→젓기 자동 재생 |
| **젓기** | 캔버스 드래그(현 wobble 인터랙션 유지) | 시뮬레이션 효과 없음 — 배고픔을 리셋하면 실시간 리듬 계약(결정 1)이 깨진다. 기포가 몇 개 올라오는 코스메틱 + 냄새 문구 살짝 노출 |
| **위치 이동** | 실온/창가/냉장고 3분할 세그먼트 컨트롤 | `location` 변경, 병이 화면 내 이동하는 연출. 냉장고는 화면 톤 차분하게 |
| **관찰** | 병 탭 → 상태 카드 | 부피·냄새·거품·마지막 밥·다음 밥 예상 시각. 정보만, 조작 없음 |
| **띄워보기** | 레시피 화면의 "물에 띄워보기" 버튼 | 무료 확인 의식: 뜨면 "지금 굽기 좋아요"(activity ≥ 0.7), 가라앉으면 남은 시간 힌트. 실제 float test |
| **빵굽기** | 레시피 탭 → 레시피 선택 → 확인 1버튼 | §5 |

밀가루·물은 무한(결정 10 — 경제 없음). 유한 자원은 discard 통과 mass뿐.

## 4. 성장 단계

게이트는 `max(요구 사이클, 요구 일수)` — 둘 다 충족해야 승급(연타 방지 + 실제 시간 흐름 보장).

| 단계 | 이름 | 조건 | 기간(성실 플레이) | 해금 |
|---|---|---|---|---|
| 0 | 갓 반죽 | 생성 직후 | D1~2 | 스크립트 온보딩. D2 **가짜 부풀기** 이벤트(실제 현상): 크게 부풀고 "곧 조용해져요. 정상이에요" |
| 1 | 잠잠기 | 3사이클·3일 | D3~5 | 침묵기. 부피 표현 ×0.3 억제. "이 시기는 원래 조용해요" |
| 2 | 첫 기포 | 7사이클·5일 | D5~7 | discard 통 개방, **팬케이크·크래커** 해금 |
| 3 | 어린 르방 | 12사이클·8일 | 주 2 | **플랫브레드·포카치아** 해금, 1:2:2 비율 해금, 냉장 보관 해금 |
| 4 | 성숙 르방 | 21사이클·15일 | 주 3~4 | **식빵·바게트·깜빠뉴** 해금, 1:5:5 해금 |
| 5 | 노포 | 45사이클·30일 | 한 달+ | **호밀빵·통밀 깜빠뉴** 해금, 병 이름표(도감 표지에 표시) |

신생 1주는 튜토리얼과 온보딩을 겸한다(§8 첫 실행). 부풀기 억제·가짜 부풀기·침묵기는 실제 스타터의 첫 주 그대로.

## 5. 레시피·빵굽기 루프

### 5-1. 레시피 트리

**discard 레시피** (discard 통 소비, 판정 없음 — 활용이 목적):

| 레시피 | 비용 | 해금 |
|---|---|---|
| 팬케이크 | discard 100g | 2단계 |
| 크래커 | discard 80g | 2단계 |
| 스콘 | discard 150g | 3단계 |

**빵 레시피** (병에서 르방 떼기 = mass 소모, 상태 판정):

| 레시피 | 르방 비용 | 산미 선호 | 판정 엄격도 | 해금 |
|---|---|---|---|---|
| 플랫브레드 | 30g | 0~60 | 관대 | 3단계 |
| 포카치아 | 50g | 0~40 | 관대 | 3단계 |
| 식빵 | 80g | 0~30 | 보통 | 4단계 |
| 바게트 | 60g | 10~35 | 엄격 | 4단계 |
| 깜빠뉴 | 100g | 15~45 | 엄격 | 4단계 |
| 호밀빵 | 80g | **40~75** | 보통 | 5단계 |
| 통밀 깜빠뉴 | 120g | 20~50 | 엄격 | 5단계 |

호밀빵은 시큼 상태의 구원 — 방치돼 시어진 르방이 오히려 적기. 실제 호밀 사워도우가 그렇다.

### 5-2. 굽기 메커니즘

1. **게이트**: 단계 충족 + `mass ≥ 비용 + 60g`(씨앗 60g은 절대 소모 불가 — 영구 사망 없음 계약의 물리적 보장).
2. **판정**: `점수 = 0.6 × activity(굽는 순간) + 0.4 × 산미적합도`(선호 범위 안 1.0, 벗어난 만큼 감점, 관대/엄격이 감점 기울기).
3. **등급**: ≥0.85 "최고예요" / ≥0.6 "잘 구웠어요" / 그 외 "조금 납작해요. 그래도 맛있어요" — 실패 없음, 코지.
4. 급여로 mass를 불리고(1:2:2=300g, 1:5:5=480g) 피크에 맞춰 굽는 것이 실제 르방 증량-굽기 리듬 그대로: **급여가 빌드, 피크가 굽기 창**.

### 5-3. 도감

빵마다 최고 등급·횟수·첫 굽기 날짜. 미해금은 실루엣 + 해금 힌트 한 줄. 레시피 탭은 첫날부터 실루엣 도감이 채워져 있어 빈 탭이 아니다(품질 기준 충족).

- 2:00 다음 밥 알림 예약 확인 문구("내일 아침쯤 배고파져요") 보고 닫기

**저녁 세션 (19:30, 3분)**
- 0:00 열기 → 르방이 피크 근처로 부풀어 있음(아침 1:2:2의 결과)
- 0:20 띄워보기 → "지금 굽기 좋아요"
- 0:40 깜빠뉴 굽기(르방 100g) → 판정 연출 → "잘 구웠어요" 등급
- 2:00 mass가 줄었으니 1:1:1 밥주기 → 닫기

**냉장 유지 주간(바쁜 주)**: 일요일에 밥 주고 냉장고로 → 다음 일요일 알림 1건 → 꺼내서 실온 복귀·밥 → 다시 냉장. 주 1회 1분 세션.

비율 선택이 곧 스케줄 퍼즐이다: "피크를 내 일상 어디에 앉힐까"가 이 게임의 조용한 전략층.

## 7. 알림 설계 (Capacitor Local Notifications)

**원칙**: 상태 변화(급여·이동·설정)마다 `cancelAll → 현재 상태에서 전량 재예약`. 하루 최대 2건. 조용 시간(기본 22~08시, 로컬 시각)에 걸리면 다음 08:00으로 클램프. 시뮬레이션은 epoch만 쓰고, 로컬 시각은 알림 클램프에만 쓴다.

| 시점 | 문구 | 비고 |
|---|---|---|
| 배고픔 진입 예측 시각 | "밥 시간이에요" | 기본 알림 |
| 무응답 +24h | "괜찮아요. 시간 될 때 밥 주세요" | 1건만 |
| 시큼 진입 예측 | "거품이 가라앉기 시작했어요" | 무응답 시에만 |
| 휴면 진입 예측 | "르방이 깊이 잠들었어요. 언제든 깨울 수 있어요" | 이후 침묵 — 스팸 금지 |
| 냉장 보관 시 | 주 1회 "일주일이 지났어요. 밥 줄 때가 됐어요" | 위 알림 대신 이것 하나 |
| 굽기 예약 시(선택) | "슬슬 부풀고 있어요" (피크 30분 전) | 사용자가 띄워보기 화면에서 "피크에 알려주기"를 켠 경우만 |

문구는 전부 담백·시스템어 0. "활성도" "phase" 같은 내부 용어 금지. 죄책감 유발 문구 금지 — 휴면 이후로는 앱이 침묵한다.

## 8. 엣지케이스

**2주 방치**: catch-up이 구간별로 산미를 적분(활발→배고픔→시큼→휴면 각 구간 요율)하고 휴면 고정점에 안착. 화면: 회색빛 반죽 + 훅치 층, 숨쉬기 정지. 메인 버튼이 "깨우기"로 바뀌고 부활 의식(§2-5) 시작. 문구: "괜찮아요. 르방은 잘 버텨요." maturity·도감 보존.

**시계 역행**: `elapsed = max(0, now − lastSimulatedAt)`. `now < lastSimulatedAt − 5분`이면 새 타임라인 수용 — `delta = lastSimulatedAt − now`만큼 **저장된 모든 타임스탬프**(`createdAt`·`lastFedAt`·`lastSimulatedAt`·도감 `firstAt`, 향후 추가 필드도 이 규칙을 상속)를 함께 당겨 **상대 간격을 보존**한 채 재정박. 나이가 음수가 되거나 단계가 퇴행할 수 없고, 진행 이득도 손실도 없으며 크래시도 없다. 알림 전량 재예약. 시계 앞으로 돌리기는 그냥 정직한 catch-up(치트지만 실제 르방도 시간이 흐르면 그렇게 된다 — 막지 않는다).

**자정 넘김·DST**: 시뮬레이션에 달력 연산이 없으므로(epoch 차이만 사용) 특수 처리 자체가 없다. 로컬 날짜는 알림 조용 시간 클램프에만 쓰인다.

**첫 실행 온보딩**: 저장 없음 → 창조 의식: 밀가루+물 섞기 인터랙션(드래그로 젓기) → `createdAt` 기록 → 0단계 스크립트 주간(§4)이 튜토리얼을 겸한다. D2 가짜 부풀기·D3~5 침묵이 "매일 열어볼 이유"를 만들면서 실제 스타터 첫 주를 그대로 가르친다.

**저장 손상**: JSON 파싱 실패 → Capacitor Preferences 미러에서 복원 시도 → 둘 다 실패 시에만 첫 실행 취급. 저장 시점: 모든 행동 직후 + `visibilitychange` + 30초 간격. `schemaVersion` 사다리로 마이그레이션.

**catch-up 상한**: 단일 advance 60일 캡. 휴면+산미 100 포화가 고정점이므로 관측 가능한 차이 없음.

**급여 연타**: maturity는 유효 6h 게이트로 미적립, 산미 희석은 정상 동작(무해), mass는 재설정뿐 — 착취 불가.
